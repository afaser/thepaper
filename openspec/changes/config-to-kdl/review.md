# Ревью реализации по алгоритму AGENTS.md

Объект: `Cargo.toml`, `Cargo.lock`, `src/config.rs`, `src/config_document.rs`, `src/main.rs`, `src/app.rs`, `src/paths.rs`, `README.md`. Каждый шаг — записанный результат; найденные признаки исправлены до прогона.

## Шаг 1. Файлы

- `config.rs` — `Config` и его конструктор `load`, семантика опций, геттеры, namespace-ы, тесты. Одна тема — конфигурация. Свободные `required_string`/`optional_string`/`blur_radius`/`app_id_prefix` читают `ConfigDocument`, не `Config`, и вызываются только из `Config::from_document` — остаются в файле потребителя. `ensure_video_file` — проверка того же алгоритма у единственного вызова.
- `config_document.rs` — `ConfigDocument` (разобранный KDL-документ и его форма), предикаты валидации, тесты. Одна тема — документ KDL.
- `main.rs` — только `mod config_document;` в алфавитном порядке; логики не добавлено.
- `app.rs` — один вызов геттера `blur_radius()`, своей логики нет.
- `paths.rs` — одна строка пути `config.kdl`.
- `Cargo.toml` — обмен `toml`/`serde` на `kdl`; `Cargo.lock` перегенерирован сборкой.
- `README.md` — KDL-пример, миграция TOML, миграция `video-wallpaper`; дублей блока нет.

Ответ на «чьи поля читает функция»: `required_string`, `optional_string`, `blur_radius`, `app_id_prefix` читают `ConfigDocument::document` через `value`, `self` — ни разу, это свободные функции файла `config.rs`; методы `Config` читают его собственные поля.

## Шаг 2. Сущности

- `ConfigDocument` — инвариант «только известные опции, без повторов, ровно один аргумент, без свойств и детей» ставит `ConfigDocument::new`; поле приватное; поведение — `value`. Контейнер `KdlDocument`, derive `Debug, Clone`; `PartialEq` не нужен.
- `Config` — инвариант «непустой существующий `video_path`, `blur_radius` в `1..=64`, непустой `app_id_prefix`» ставит `Config::load`; поля приватные, доступ — геттеры. derive `Debug, Clone`; `PartialEq` не нужен.
- `OPTIONS` — значение-набор, не сущность; отдельного типа не требует.
- Роль в данных без имени (кортеж, сырой слайс) не появилась.
- Имена `ConfigDocument` и `Config` с другими типами подсистемы не совпадают.

## Шаг 3. Дубль и состояние

- `required_string` делегирует в `optional_string`; `blur_radius` и `app_id_prefix` — разные поля, не дубль по измерению.
- `is_duplicated` проверяет повтор предикатом по `document.nodes()`, без вспомогательной карты или флага.
- `has_properties` и `argument_count` — два разных предиката формы узла; булевых флагов и массивов состояния нет.
- Сообщение о диапазоне `1..=64` существует в одном месте.

## Шаг 4. Поток

Направление: текст файла → `ConfigDocument` (синтаксис и форма) → `Config` (типы, дефолты, диапазон, файл видео). Данные не текут назад; `Config::load` — граница чтения файла. `ConfigDocument` передаётся по ссылке, `Config` возвращается по значению; изменяемого чужого состояния нет. Между фазами течёт `ConfigDocument`, внутренние узлы не размазаны по сигнатурам.

## Шаг 5. Тело

- `Config::load`: guard-ошибки чтения и разбора, затем один вызов `from_document` с контекстом пути.
- `Config::from_document`: плоские именованные `let`, проверка файла отдельной функцией.
- `ConfigDocument::new`: разбор → `validate_nodes`; `validate_node` — цепочка guard-ов, вложенности нет.
- `blur_radius`: `let … else` для отсутствия/типа, `u32::try_from` на границе, предикат `is_blur_radius` в `filter`; без `as`-кастов и `unwrap`.
- `parse_error` берёт первое диагностическое сообщение; паники в рабочем коде нет.
- Namespace-ы читают собственное поле `app_id_prefix`.

Найдено и исправлено:

- README ставил миграционный блок между примером и объяснением кодека и утверждал, что комментарии не меняются; блок перенесён после объяснения, `#` → `//` задокументировано.
- В design.md утверждалось, что `default-features = false` убирает `miette`; фактически `miette` обязательна в `kdl` 6.5. Формулировка исправлена по `cargo tree`.
- Задача 3.2 проверяла `config.<field>` без учёта геттеров; команда уточнена до доступа к полю без `(`.
- Задача 4.3 требовала пустой `rg` по README, хотя миграционный блок обязан называть `config.toml`; проверка разделена на код и README.

## Шаг 6. Прогон

- `cargo fmt --check` — успешно.
- `cargo clippy --all-targets` — успешно, предупреждений нет.
- `cargo test` — 18 тестов, все успешны.
- Границы: пустой документ, отсутствие `video_path`, пустой `video_path`, несуществующий файл, неверные типы, `blur_radius` `-1/0/65` и `1/64`, дефолты, полный конфиг; consuming-операций у конфигурации нет.
- Контейнер по «Среда»: неизвестная опция → `invalid config /config.kdl: unknown option \`blur_radius2\``, код 1 до Wayland; валидный KDL → семантическая ошибка о видео, ошибки разбора нет.
- Визуальный прогон обоев не выполнялся: изменение не затрагивает рендер; конфигурационная поверхность проверена запуском бинаря в контейнере.
- `openspec validate config-to-kdl --strict` — успешно.
