## Context

Имя `video-wallpaper` зашито в шесть групп мест: манифест (`[package]` и `[[bin]]`), пути XDG (`paths.rs`), префикс namespace-ов (`config.rs`), лок и текст ошибки (`instance.rs`), переменные окружения (`main.rs`, `decoder.rs`), метки GPU-объектов (`app.rs`, `render.rs`), плюс `flake.nix`, README и домен спек `openspec/specs/video-wallpaper/`. `Cargo.lock` содержит запись пакета и перегенерируется сборкой.

Единственное имя, которое пользователь дал проекту, — каталог репозитория `thepaper`; всё остальное придумали агенты предыдущих изменений.

Незаархивированное изменение `move-video-wallpaper-to-src` содержит дельту по пути `specs/video-wallpaper/playback/`; после переименования домена её архив создал бы заново каталог `openspec/specs/video-wallpaper/`.

## Goals / Non-Goals

**Goals:**

- Одно имя `thepaper` во всех пользовательских и внутренних идентификаторах.
- Чистый переход: старые пути и переменные не поддерживаются, чтобы имя не жило в коде «на всякий случай».
- Домен OpenSpec-спек приведён к `thepaper/`, история изменений не переписана.

**Non-Goals:**

- Обратная совместимость: фолбэки на `~/.config/video-wallpaper/`, старый лок, `VIDEO_WALLPAPER_*` не добавляются.
- Переименование заархивированного изменения `add-video-wallpaper` и имени изменения `move-video-wallpaper-to-src` — это исторические записи.
- Изменение поведения: декод, поверхности, овервью, game-mode, формат конфигурации — как в текущих спеках.

## Decisions

**Манифест.** `[package] name = "thepaper"`. Таблица `[[bin]]` удаляется: имя бинаря по умолчанию совпадает с именем пакета, а `src/main.rs` — путь по умолчанию; явная таблица дублирует то, что cargo выводит сам. `Cargo.lock` не правится руками — перегенерируется `cargo build`.

**Пути XDG.** Меняется только лист каталога: `paths.rs` → `thepaper`, `config.toml` и каталог кеша сохраняют структуру. Лок — `thepaper.lock` в `$XDG_RUNTIME_DIR` (фолбэк — каталог кеша, как сейчас). Альтернатива «читать старый путь, если новый отсутствует» отклонена: пользователь просил одно имя, а фолбэк оставляет второе имя в коде и создаёт неявный приоритет двух конфигов.

**Переменные окружения.** `THEPAPER_LOG` и `THEPAPER_DRM_RENDER_NODE`; старые имена не читаются. Алиасы отклонены по той же причине, что и фолбэк путей.

**Префикс поверхностей.** `default_app_id_prefix` → `thepaper`; формы `<prefix>-live-<output>` и `<prefix>-blur-<output>` не меняются, поэтому переопределение `app_id_prefix` в конфиге продолжает работать. Правило niri у пользователя (`match namespace="^video-wallpaper-blur-"`) живёт вне репозитория и обновляется вручную; README получает блок миграции.

**Литералы вместо модуля констант.** Имя остаётся литералом в четырёх местах (`paths.rs`, `config.rs`, `instance.rs`, `main.rs`) и в env-именах. Новый модуль `identity.rs` с константами отклонён: по AGENTS.md отдельный файл получает концепт (сущность с операциями или задачу, оформленную типом), а набор строковых констант — не сущность; выигрыш от единственного места не окупает новый файл в плоском каталоге.

**OpenSpec.** `git mv openspec/specs/video-wallpaper openspec/specs/thepaper`, заголовки `# <capability> Specification` переписываются на новый домен. Дельта незаархивированного `move-video-wallpaper-to-src` переносится `git mv .../specs/video-wallpaper .../specs/thepaper`; тексты его proposal/design не трогаются. Если изменение успеют заархивировать до применения, пути не будет — шаг становится no-op и проверяется условием.

**Проверка.** `rg` по старому имени вне `openspec/changes/archive/` и вне исторических текстов `move-video-wallpaper-to-src`; `cargo build`, `cargo test`, `cargo clippy`; `openspec validate`. Запуск — в контейнере по «Среда»; без hardware GPU визуальный прогон не выполняется, граница фиксируется.

## Risks / Trade-offs

- [Правило niri перестанет матчить blur-поверхность, и овервью потеряет блюр молча] → блок миграции в README с точным заменяемым правилом и `spawn-at-startup "thepaper"`; в задачах — проверка README на оба места.
- [Конфиг по старому пути перестанет читаться, приложение завершится с ошибкой] → README указывает `mv ~/.config/video-wallpaper ~/.config/thepaper`; чистый отказ виден сразу и не маскирует переезд.
- [Старый кеш транскода останется мёртвым грузом в `~/.cache/video-wallpaper/`] → README предлагает удалить каталог; приложение его не читает.
- [Перенос домена спек конфликтует с будущим архивом `move-video-wallpaper-to-src`] → путь его дельты переносится в этом же изменении; порядок «архив до/после» перестаёт влиять.

## Migration Plan

1. Применить изменение, собрать `thepaper`.
2. `mv ~/.config/video-wallpaper ~/.config/thepaper`; `rm -rf ~/.cache/video-wallpaper`.
3. В `~/.config/niri/config.kdl`: `namespace="^thepaper-blur-"`, `spawn-at-startup "thepaper"`.
4. Запустить `thepaper`; первый запуск создаёт новый кеш и `thepaper.lock`.

Откат — обратный `git revert` плюс возврат каталога конфигурации; данные не мигрируют, поэтому откат безопасен.
