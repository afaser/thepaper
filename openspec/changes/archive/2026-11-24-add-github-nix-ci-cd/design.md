## Context

`nix profile add github:afaser/thepaper` подставляет готовые store-пути только из бинарного кеша. Cachix и другие substituter'ы отклонены; кеш GitHub Actions подстановку не даёт, а релизные ассеты не являются бинарным кешем: narinfo ссылается на относительный `nar/<hash>.nar`, а у ассетов нет вложенных путей. Значит, готовый бинарь без стороннего кеша и без компиляции Rust отдаёт только пакет, который сам скачивает релизный ELF и патчит его под библиотеки nixpkgs устанавливающего.

Исходное состояние: `flake.nix` содержит только `devShells.x86_64-linux.default`, `inputs.nixpkgs` — `path:/nix/store/...`; `packages` нет. Версия — `0.1.0` в `Cargo.toml`. Приложение линкуется с `libavcodec`/`libavformat` (`ffmpeg-sys-next`), запускает `ffmpeg`/`ffprobe`/`vainfo` как процессы, Vulkan загружает через loader. `--help` и `--version` обрабатываются clap до чтения конфига и инициализации GPU. Тесты — два модуля парсинга конфига, герметичны.

Требования — `specs/thepaper/distribution/spec.md`; мотивация — `proposal.md`.

## Goals / Non-Goals

**Goals:**

- `default`/`thepaper` ставят ELF из GitHub Release; в сборке нет `cargo`/`rustc`.
- `source` собирает текущие исходники с тестами для CI и разработки.
- Переносимый флейк: единственный вход — nixpkgs с GitHub.
- Один номер версии — один неизменяемый релиз: без перезаписи ассетов и без переноса тегов.
- Релиз проверяется до публикации и доводится до ветки только после публикации.

**Non-Goals:**

- Бинарный кеш, Cachix, attic, self-hosted substituter.
- Статическая сборка, AppImage, `nix bundle`.
- Кросс-сборка, aarch64, musl.
- Прогон GPU/визуального сценария в CI.
- Изменение кода приложения.

## Decisions

**Пакет из релиза вместо кеша.** `default` — `fetchurl` из `release.json` плюс общий конструктор `nix/release-package.nix`: `stdenv.mkDerivation`, `autoPatchelfHook`, `runtimeDependencies`, `makeWrapper`. Зависимости из `cache.nixos.org`; компилируется только ELF-патч и wrapper. Альтернативы (Cachix, кеш Actions, релиз как HTTP-кеш, свой attic) отклонены ранее и не решают задачу без внешнего сервиса.

**Один конструктор для установки и проверки.** `nix/release-package.nix` принимает `{ version, src }`, где `src` — уже распакованный архив или `fetchurl`; `flake.nix` передаёт `fetchurl`, release-workflow — локальный путь к архиву. `default` и предпубликационная проверка используют один и тот же набор `buildInputs`, `runtimeDependencies`, `installCheckPhase`, wrapper. Иначе проверка в workflow доказывала бы не тот пакет, который ставит пользователь. Конструктор доступен как `lib.mkReleasePackage` для `nix build --impure --expr` из workflow.

**Ассет — несобранный ELF.** `source` кладёт ELF в `$out/libexec/thepaper`, wrapper — в `$out/bin/thepaper`. Архив содержит файл `thepaper` в корне. Store-пути CI-замыкания в ассет не попадают, двойной обёртки нет. `fetchurl` распаковывает архив, конструктор кладёт ELF в `libexec` и оборачивает заново.

**Версия принадлежит артефакту.** `source.version` — из `Cargo.toml`; `default.version` — из `release.json`; `installCheckPhase` сравнивает `thepaper --version` с переданной версией. После повышения `Cargo.toml` до релиза `default` намеренно отдаёт предыдущий бинарь и предыдущую версию. Требовать совпадения `default.version` с Cargo постоянно нельзя: хеш ассета новой версии появляется только после сборки. Совпадение обязательно на релизном коммите, и release-workflow это проверяет. Bootstrap без `release.json` даёт `default = source`, то есть временно компилирует Rust; это явное исключение до первого релиза.

**Неизменяемый релиз вместо повторной публикации.** Имя ассета фиксировано (`thepaper-x86_64-linux.tar.gz`), потому что версия уже уникальна. `--clobber`, `git push --force`, повторная загрузка и перенос тега запрещены. GitHub immutability делает такие попытки невозможными после публикации; протокол не должен на них опираться.

Последовательность первого релиза:

1. Проверить входную версию (semver, равна `Cargo.toml`), ветку запуска и отсутствие опубликованного `vX`.
2. Собрать `.#source` из текущего коммита.
3. Создать детерминированный архив ELF и вычислить SRI-хеш.
4. Собрать бинарный пакет из локального архива через `lib.mkReleasePackage` и проверить `--version`, `--help`, RPATH. Публичный URL ещё не нужен.
5. Записать `release.json`, создать локальный пин-коммит и тег `vX`.
6. Отправить только тег. Коммит становится доступен, ветка ещё не меняется; trunk продолжает работать по прежнему релизу.
7. Создать draft `vX` с `--verify-tag`, загрузить ассет, опубликовать (`gh release edit vX --draft=false`).
8. Проверить скачивание по публичному URL и `nix build .#default` из пин-коммита.
9. Отправить пин-коммит в ветку запуска fast-forward.

Draft создаётся после тега, а публикуется после загрузки. Ошибка до шага 7 удаляет draft и тег, созданные этим запуском; ветка не тронута. Ошибка после публикации не удаляет релиз и не отправляет пин: опубликованный тег неизменяем, а несовместимая версия исправляется только новой версией.

**Повторный запуск.** Если `vX` уже опубликован, workflow не собирает и не загружает ничего. Если пин-коммит уже в ветке — успех. Иначе он пытается fast-forward отправить коммит тега в ветку; если ветка ушла вперёд, запуск падает без force. Если существует только draft (прерванный запуск), draft и тег удаляются и релиз начинается заново, поскольку публикации ещё не было. Одновременные запуски сериализуются общей группой `concurrency`.

**Обновление nixpkgs — новая версия.** Обновление `flake.lock`, меняющее зависимости бинаря, делается вместе с повышением версии в `Cargo.toml`. Release-workflow запускается на ветке обновления, публикует `vNew` и отправляет пин в эту ветку; тогда `checks.default` проверяет уже новый ассет до слияния. Пересборка того же номера версии под новый nixpkgs не предусмотрена: это потребовало бы перезаписи неизменяемого ассета или переноса тега.

**Vulkan и RPATH.** `autoPatchelf` добавляет пути только для `DT_NEEDED` и `.note.dlopen`; `buildInputs` сам по себе не кладёт каталог в RPATH. `vulkan-loader` загружается через `libloading`, поэтому оба пакета задают `runtimeDependencies = [ vulkan-loader libglvnd ]` (либо явный `appendRunpaths`). `patchelf --print-rpath` в проверке фиксирует результат.

**Общий FFmpeg для devShell и пакетов.** Один атрибут (`ffmpeg` или `ffmpeg_7`, выбор по фактической сборке) передаётся в `devShell`, `source` и бинарный пакет. Иначе локальная разработка линкуется с другим мажором, чем CI. Мажор фиксируется на время жизни релиза; его смена — новая версия.

**CI без секретов.** `ubuntu-latest`: checkout, установка Nix через `cachix/install-nix-action` (только установщик, кеш не используется), проверка `jq -e '[.. | objects | select(.type? == "path")] | length == 0' flake.lock`, `nix flake check --print-build-logs`, `nix build .#default`, `--help` и сверка `--version` с `nix eval --raw .#default.version`. Форк-PR не требует секретов; сеть нужна для nixpkgs и ассета. `checks.source` и `checks.default` дают обе сборки внутри `flake check`.

**Публикация.** Release-workflow требует `permissions: contents: write`. Push ветки и тега от `GITHUB_TOKEN` работает только если защита ветки и тегов разрешает actor workflow; PAT сам по себе не обходит правило, требующее pull request. Это предварительное условие в README, а не обход защиты.

## Risks / Trade-offs

- [Ошибка после публикации требует новой версии] → принято ради неизменяемости; локальная проверка до публикации снижает вероятность, а `--version`/RPATH ловят неверный артефакт.
- [Обновление nixpkgs требует версии и релиза до слияния PR] → явный процесс; иначе `checks.default` красный, и установка на trunk могла бы остаться с несовместимым бинарём.
- [Релиз с ветки PR может остаться сиротой, если PR отклонён] → версия выпускается только с готовой к слиянию ветки; удаление опубликованного релиза невозможно при immutability и не автоматизируется.
- [`default` отстаёт от `Cargo.toml`] → README различает `.#default` (последний релиз) и `.#source` (исходники); CI сверяет версию с `release.json`.
- [Установка требует сеть: ассет и библиотеки из `cache.nixos.org`] → следствие отказа от кеша; офлайн-установка не поддерживается.
- [autoPatchelf не проверяет версии glibc-символов] → ассет и установка используют один `flake.lock`; после смены lock нужна новая версия и проверка `checks.default`.
- [Vulkan ICD остаётся системным] → RPATH даёт loader; драйвер GPU пользователя вне пакета, как и раньше.
- [`--help` и `--version` не доказывают playback] → проверка ограничена загрузкой ELF и clap; визуальный прогон остаётся локальным в контейнере.
- [Первый релиз требует вручную настроить Actions] → workflow падает без прав; README перечисляет предусловия.

## Migration Plan

1. Перепинить nixpkgs, добавить общий набор пакетов, `source`, bootstrap-`default`, `lib.mkReleasePackage`, `checks`, `apps`; локально `direnv allow`, `nix build .#source`, `nix flake check`.
2. Добавить CI и проверить зелёный PR на bootstrap-`default`.
3. Добавить release-workflow; выпустить `0.1.0` на trunk и проверить установку из trunk и тега.
4. Обновить README; проверить инструкции.
5. Проверить сценарий обновления nixpkgs на следующей версии.

Откат — revert коммитов флейка и workflow. Опубликованные релизы и теги не трогаются; удаление `release.json` возвращает bootstrap-сборку.
